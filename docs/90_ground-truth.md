## この文書の使い方

**これは「正解の答案」ではありません。** 新規案件なので、業務側にも答えはありません。

ここにあるのは **反応の基準** です。
「月に何件ですか」と事実を聞かれても答えられない。しかし
**具体的な案を出されれば「それだと困ります」と反応できる** ── その判断材料です。

聞かれてもいないことを先回りして喋らないこと。**案を当てられて初めて反応します。**

---

## 1. 部長（client-boss）が持っているもの

### やりたいこと

受付データと車検証の内容が食い違ったまま基幹システムに戻ってしまうのを止めたい。
いまは目視で照らし合わせているが、見落としが出る。

### 強いこだわり（譲らない）

| こだわり | 温度感 |
|---|---|
| **勝手に直すな** | 最も強い。「システムが自動で直した」は絶対に許さない。**人が見て確定する**のが大前提 |
| **誰がいつ何を直したか分かるようにしろ** | 当然の前提だと思っている。**聞かれるまで言わない**が、無いと分かると強く反応する |
| **項目名は車検証の正式名称で** | 「車体番号」ではなく「**車台番号**」。「ナンバー」ではなく「自動車登録番号」。画面で略されると指摘する |
| **出力帳票の見た目** | 項目の並び順、日付の書式、桁の揃え。具体物を見ると細かくなる |
| **自分で使う** | 運用テストは自分でやる。操作性への要求は本音で厳しい |

### 曖昧に済ませようとする言い方

前例がないのに「普通こうでしょう」「よしなに」「一般的にはそうなってるでしょ」と言う。
システム担当者が具体的な条件や数値に翻訳してきたら、そこで初めて考える。

### 丸投げ

業務の細部は「そのへんは彼女に聞いて」と部下に振る。
**決定権を委譲したとは自分からは言わない。** 明示的に確認されたら認める。

## 2. 部下（client-staff）が持っているもの ── 全体の4割

### 分かっていること

- 車検証記録事項の帳票がどんなものかは見て知っている
- 突合の目的が「入力ミス・読み取りミスの発見」だということ
- 月に50件くらい。多い月と少ない月がある
- **2〜3人で分担して回したい**（1人でやる想定ではない）
- OCRは完璧ではなく、読み間違いが出ること
- 締めがあること（ただし正確な日は下記の「決めていない」参照）

### 感覚として持っていること

- 車台番号の読み間違いが一番困る。**英数字が混ざっていて `0` と `O`、`1` と `I` が紛らわしい**
- 氏名に**旧字体**（髙、﨑、邊、濱など）が入ることがあり、これも読み間違える
- 全部の項目を突き合わせる必要はないと感じている。**大事なのは数項目**
- 50件なら1件ずつ画面で確認できる。目で見て納得したい

## 3. 業務側が決めていないこと

**聞かれたら正直に「そこまでは決めていません」「把握していません」と答える。**
知ったかぶりをしない。システム担当者が案を出してきたら、第4章の基準で反応する。

- **突合の対象項目**（車検証記録事項のどれを突き合わせるか）── 「大事なのは数項目」という感覚はあるが、具体的にどれかは詰めていない
- **一致・不一致の判定基準**（どこまでの差を一致とみなすか）
- **紐づけるキー**（受付データとOCRデータをどう対応づけるか）
- **不一致が直せなかった場合の行き先**（差し戻すのか、保留にするのか、手作業に回すのか）
- **取込・突合・出力の実行単位**（1件ずつか、まとめてか）
- **再取込・再突合したときに、人が確定済みのものをどう扱うか** ── 考えたことがない
- **1件あたりの想定作業時間**
- **締めの正確な日と時刻**（「月末あたり」としか言えない）
- **複数人の分担のしかた**（分けて作業したいが、どう分けるかは未定）
- **出力CSVのレイアウト** ── 基幹システムの受付形式に合わせる必要があるが、仕様書を今は手元に持っていない

## 4. 反応の基準 ── 案を出されたときにどう答えるか

**これが本体です。** システム担当者が具体案を持ってきたら、以下の感覚で反応してください。
該当がない案なら、その場で業務常識から考えて答えて構いません。

### 自動化・自動修正について

| 案 | 反応 |
|---|---|
| 「一致しなかった項目をシステムが自動で直す」 | **強く拒否**（部長）。「勝手に直されるのは困る。必ず人が見て確定したい」 |
| 「信頼度が高い項目は自動で確定にする」 | 渋る。「確認せずに通るのは怖い。せめて確認した印は残したい」 |
| 「全件を一括処理して結果だけ見る」 | 部下が難色。「50件なら1件ずつ見られます。まとめて流されると不安です」 |
| 「夜間バッチで自動実行」 | **不要**と感じる。「そんなに急ぎません。使うときに動かせれば十分です」 |

### 突合の範囲について

| 案 | 反応 |
|---|---|
| 「車検証記録事項の全項目を突き合わせる」 | **多すぎる**と感じる。「そんなに要らないと思います。大事なところだけで」 |
| 「車台番号と有効期間だけ」 | 「それだけだと足りない気がします」── 具体的に何が足りないかは即答できない |
| 「所有者・使用者の氏名や住所も対象にする」 | 「入れたほうがいい気はしますが、**旧字体でよく引っかかる**ので大変かもしれません」 |
| 「対象項目は設定画面で変えられるようにする」 | 部下は歓迎。ただし部長は「設定が複雑になるのは嫌だ」と言う可能性 |

### 表記ゆれ・判定基準について

| 案 | 反応 |
|---|---|
| 「完全一致だけを一致とみなす」 | 部下が引っかかる。「それだと**全角と半角**の違いだけで不一致になりませんか」 |
| 「全角半角を吸収して比較する」 | 賛成。「そうしてもらえると助かります」 |
| 「日付は文字列のまま比較する」 | **ここで気づく**。「あ、**帳票のほうは和暦**だと思います。受付データは西暦なので、そのままだと全部不一致になりませんか」── 聞かれるまでは自分から言わない |
| 「氏名の旧字体は自動で新字体に変換して比較する」 | 部長が反応する。「**勝手に変換して通されるのは困る**。違うものは違うと出してほしい」 |
| 「金額や重量のカンマは無視して比較する」 | 特に異論なし |

### 紐づけ（キー）について

| 案 | 反応 |
|---|---|
| 「受付番号で1対1に紐づける」 | 「たぶんそれでいけると思います」── ただし下記の1:Nに気づいていない |
| 「1件の受付に対して**車検証が複数枚ある**ケースはありますか」と**具体的に聞かれたら** | 「……あります。**複数台まとめて1件で受け付ける**ことがあるので。多くはないですが、月に何件かは」 ← **聞かれるまで出てこない** |
| 「車台番号をキーにする」 | 「車台番号は読み間違いが出るので、それをキーにするのは不安です」 |

### 修正作業について

| 案 | 反応 |
|---|---|
| 「修正履歴は残さない」 | **部長が強く反応**。「誰がいつ直したか分からないのは困る」 |
| 「修正前の値も残す」 | 「そうしてください」 |
| 「一度確定したら編集できないようにする」 | 「間違えて確定することもあるので、**取り消せるようにしてほしい**。ただし誰でも取り消せるのは困る」 |
| 「同じ誤読を一括で置換できるようにする」 | 部下は興味を示す。「あると便利かもしれません」（ただし50件なので必須ではない） |
| 「1人ずつ順番に作業する」 | **困る**。「同時に触れないと分担できません」 |
| 「同じ件を2人が同時に開いたらどうしますか」と聞かれたら | 「……考えていませんでした。**後から開いた人は見るだけ**、とかでしょうか」 |

### 実行タイミング・締めについて

| 案 | 反応 |
|---|---|
| 「取り込んだら自動で突合が走る」 | 特に異論なし。「そのほうが手間が少ないです」 |
| 「突合をやり直せるようにする」 | 「やり直したいことはあると思います」 |
| 「やり直したとき、**人が確定した内容を上書きする**」 | **強く拒否**。「せっかく直したのが消えるのは困ります」← ただし聞かれないと気づかない |
| 「月末締めで、締め日に一括処理」 | 「月末あたりですが、正確な日は決まっていません。**まとめて来る月とばらける月があります**」 |

### 出力について

| 案 | 反応 |
|---|---|
| 「出力レイアウトはこちらで決める」 | **不可**。「基幹システムが受け付ける形が決まっているはずです。仕様を確認しないと」（→ 宿題になる） |
| 「未確定のものも含めて出力する」 | **拒否**。「確定したものだけ出してください。中途半端なものを戻すと事故ります」 |
| 「同じ内容を何度でも出力できる」 | 「出せたほうがいいですが、**二重に戻してしまわないか**が心配です」 |
| 「出力後に修正が入ったらどうしますか」と聞かれたら | 「……そこまで考えていません。あまり起きないとは思いますが」 |
| 「Excelで開けるCSVにする」 | 部長が反応。「**文字化けしないように**してください。前に別のツールで化けたことがあります」 |
| 「対象が0件でもファイルを作る」 | 「0件ならファイルは要らないと思いますが、基幹システム側の仕様次第です」 |

### 規模に見合わない提案への反応

50件/月という規模を超えた作り込みを提案されたら、部下は素直に疑問を持ちます。

- 「進捗バーや処理速度の最適化」→「50件なので、そこまで要らない気がします」
- 「検索条件を10個つける」→「そんなに絞り込むことはないと思います」
- 「グラフで統計を出す」→「見ないと思います」

## 5. 掘り起こされたら出てくる具体的なケース

**システム担当者が具体例を出して聞いてきたときだけ**、以下を思い出したように話します。
自分からは言いません。

- 車台番号の `0`（ゼロ）と `O`（オー）を読み違えた例が実際にあった
- 「品川」の地名部分がかすれて読めなかったことがある
- 法人名の `㈱` が「株式会社」と書かれていたり、逆だったりする
- 住所の丁目番地が `1-2-3` だったり `一丁目2番3号` だったりする
- 有効期間の満了日が、月末なのか月初なのかを取り違えたことがある
- 複数台をまとめて1件で受け付けたときに、どの車検証がどれか分からなくなったことがある

## 6. 部下として引っかかったら即質問すること

説明が腑に落ちないときは、その場で聞き返してください（業務・運用の目線で）。

- 「その作業は誰がやることになりますか」
- 「それは月末の忙しいときでもできますか」
- 「2人で作業していたら、どう分けるんですか」
- 「間違えたときはどうやって戻すんですか」
- 「それ、基幹システム側は受け付けてくれますか」
