## 1. 案件の概要

受付データと、車検証記録事項の帳票をOCRでデータ化したCSVを突合し、
食い違いを検出して直すためのツールを新規に作る。

業務の流れは `docs/10_tobe-flow.md` を参照。**④取込〜⑦出力が本ツールの範囲**で、
前後の基幹システムの操作は範囲外。

## 2. 作る機能（この4つ）＋メニュー

| # | 機能 | 概要 |
|---|---|---|
| ① | **取込** | 受付データCSVとOCRデータCSVを取り込む |
| ② | **マッチング** | 両者を突き合わせ、一致・不一致を判定する |
| ③ | **データ修正** | 不一致を人が確認して直し、確定する |
| ④ | **出力** | 別システムに戻すCSVを出力する |

加えて、**各機能への入口となるメニュー画面**を用意すること（起動時に表示）。

**この4機能の範囲で固めること。増えるなら相談すること。**

### 正式な要件は別紙

要件は `docs/11_manager-requirements.md` に一覧で渡してある。**これがスコープの基準線。**

## 3. 稼働環境

| 項目 | 内容 |
|---|---|
| 形態 | **C# デスクトップアプリ（WinForms）** |
| OS | Windows 11 |
| 配置 | 社内ネットワーク上の共有。複数端末から利用 |
| Excel | 業務端末にインストール済み（出力を開く用途で使われる想定） |

WPFではなくWinFormsとする。社内の他ツールと揃えるため。

## 4. 前後のシステムとOCR製品

| 項目 | 状況 |
|---|---|
| **受付データの入手元** | 別システム（基幹）からのCSV出力。**確定済み** |
| **OCR製品** | 導入済みの製品を使う。**確定済み** |
| OCR出力形式 | CSV。**項目単位の信頼度スコアを出力できる** |
| **出力の戻し先** | 同じ別システム。CSV取込口がある |

前後のシステム側の改修は**今回の範囲外**。こちらの都合で相手のフォーマットは変えられない。
出力レイアウトは相手が受け付ける形に合わせる必要がある。

## 6. 予算と期限

| 項目 | 内容 |
|---|---|
| 想定工数 | 小規模。1〜2人月程度（**管理者側の当たり**。実際の日程はシステム担当者の見積による） |
| リリース | 2か月後 |
| **完成目標** | **システム担当者から出た見積工数から逆算して置く。遅くともリリースの2週間前** |
| 運用テスト | リリースの1か月前から。**業務担当者本人がテストユーザ** |

**日程はシステム担当者の見積工数を基準に組むこと。** 上の1〜2人月は管理者側の当たりに過ぎない。
要件が固まった段階で工数を見積もって報告し、それを基準に完成目標を置くこと。
見積が枠に収まらないなら、日程を詰めるのではなく**スコープを削る相談をすること。**

完成目標からリリースまでの2週間は、運用テストで出た指摘の手直しとリリース準備に充てる。
**この予備を食い潰す前提の計画は立てないこと。**
