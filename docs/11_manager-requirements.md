**提示者**: システム管理者 / **提示先**: システム担当者 / **版**: 1.0

## この文書の位置づけ

**これがスコープの基準線です。** ここに書かれた要件を満たすものを作ります。

**ここに無い機能を作る場合は、管理者の承認が必要です。** 会議で業務側から要求が出たら、
この一覧に照らして「範囲内か／機能追加か」を判断し、追加なら会議の最後に諮ってください。

**書いてあるのは「何ができること」までです。** 判定基準、対象項目、レイアウト、画面の作りといった
詳細は書いていません。**それらは業務側と詰めて決めること。**

## 要件一覧

### 画面構成

| ID | 要件 | 区分 | 備考 |
|---|---|---|---|
| **R-01** | **各機能への入口となるメニュー画面があること** | 必須 | 起動時に表示する。ここから4機能の画面を開く |

### ① 取込

| ID | 要件 | 区分 | 備考 |
|---|---|---|---|
| R-11 | 受付データのCSVを取り込めること | 必須 | 別システムからの出力 |
| R-12 | OCRデータのCSVを取り込めること | 必須 | 帳票をOCR製品でデータ化したもの |
| R-13 | 取込の結果（件数・エラー）を確認できること | 必須 | エラーの内容が分かること |

### ② マッチング

| ID | 要件 | 区分 | 備考 |
|---|---|---|---|
| R-21 | 受付データとOCRデータを突き合わせられること | 必須 | 突合キー・判定基準は業務側と決める |

### ③ データ修正

| ID | 要件 | 区分 | 備考 |
|---|---|---|---|
| R-31 | 突合結果の不一致を人が確認できること | 必須 | |
| R-32 | 内容を人が修正して確定できること | 必須 | **確定は人が行う。自動確定はしない** |
| R-33 | 確定済みと未確定を区別できること | 必須 | |

### ④ 出力

| ID | 要件 | 区分 | 備考 |
|---|---|---|---|
| R-41 | 確定した内容をCSVに出力できること | 必須 | 別システムに戻すためのもの |
| R-42 | 出力のレイアウトが別システムの受付形式に合うこと | 必須 | **相手の仕様に合わせる。こちらでは決められない** |

### 非機能

| ID | 要件 | 区分 | 備考 |
|---|---|---|---|
| R-91 | C# WinForms のデスクトップアプリであること | 必須 | Windows 11 |
| R-92 | 複数の端末・複数の利用者から使えること | 必須 | 具体的な運用は業務側と決める |
| R-93 | 月50件程度の処理に耐えること | 必須 | **この規模を超える作り込みはしない** |
| R-94 | 前後の基幹システムに改修を要しないこと | 必須 | 相手方の改修費は取れない |

## 明示的に範囲外とするもの

以下は今回作りません。要求が出たら管理者に諮ってください。

- 基幹システム側の改修・機能追加
- 帳票の出力そのもの、OCR処理そのもの（① の前工程は既存の手順で行う）
- 出力したCSVを基幹システムへ取り込む処理（④ の後工程は既存の手順で行う）
- 承認ワークフロー、通知、マスタ管理
- 統計・集計・グラフ

## システム担当者への注意

- **この一覧は「何ができること」までです。** どう作るかは業務側と詰めて決めてください
- 業務側の要求がこの一覧の外に出たら、その場で約束せず**会議の最後に諮る**こと
- 規模は月50件です。**それに見合わない作り込みは削ります**
