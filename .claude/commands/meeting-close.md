あなたは**司会**です。閉会の手順を実行してください。

## 手順1: 管理者の締めパート（bookend で招集していた場合）

`sys-manager` を再度呼び、システム担当者から報告させます。

- 本日の決定事項と宿題
- **会議中に保留した機能追加の要求を一括で諮る**

管理者は 採用 / 次期 / 対象外 / 保留 で裁き、却下・先送りの際は「代わりに何を削るか」「運用で回避できないか」を問い返します。判定結果を記録します。

```bash
python scripts/record.py feature --code F-xx --judgment 次期
```

## 手順2: 読み合わせ

本日決まったことを**1件ずつ読み上げて**参加者に確認します。認識違いがあればここで直します。仮決めは「これは仮決めです」と明示すること。

**あわせて閉会前の点検を2つ。** どちらも会議全体を見渡さないと分からないので、ここでしか見つかりません。

- **未回答のまま宙に浮いている問いはないか**（CLAUDE.md 4番）。あれば答えを戻すか、宿題に落とす
- **full で招集したのに一度も発言していない参加者はいないか。** いたなら監督に報告する（招集を誤ったか、司会が振り忘れたか）
  ```bash
  python scripts/clock.py --detail   # 発言者ごとの内訳。ここに名前が出てこない招集者が該当
  ```

## 手順3: 記録を確定する

未記録の決定・宿題があればここで入れます。

```bash
python scripts/record.py decision --body "..." --status 仮|本 --by ... --utterance <発言ID>
python scripts/record.py issue --body "..." --owner ... --due ...
python scripts/record.py fact --topic "..." --body "..." --by ... --utterance <発言ID>
```

**決定には必ず根拠となった発言ID（`--utterance`）を紐づけてください。** これが後で蒸し返されたときの防御になります。

## 手順4: 閉会してビューを更新

```bash
python scripts/record.py meeting-close --summary "<会議の総括を1〜2文で>"
python scripts/views.py
python scripts/export_excel.py
python scripts/log.py --speaker "司会" --topic "閉会" --body "..."
```

## 手順5: 現在地を示し、次に開くべき会議を提案する

会議は4つの型（**要件を詰める** ／ **画面を決める** ／ **仕様を固める** ／ **運用テスト**）で進みます。
**型は番号で呼ばず、名前で呼びます。**
型ごとの**次へ進む条件**は `docs/13_meeting-flow.md` にあります（開会時の現在地判定と同じ表です）。

```bash
cat docs/13_meeting-flow.md
```

**まず現在地を言ってください。** 「本日は **要件を詰める** でした。次へ進む条件（`sys-staff` が
中核画面の設計に着手できる）はまだ満たしていません」のように、**今日の型と、その型の終了条件を満たしたかどうか**を
明示します。型の条件も「**次に誰の手が動くか**」で書いてあるので、下のゴール判定と地続きです。

**次に、本日のゴールが達成できたかを2本立てで返します。** ゴールは開会時に「誰が次に着手できるか」の形で
宣言してあります（`/meeting-open` 手順4）。判定も同じ形で返すこと。

| | 判定すること |
|---|---|
| **システム側** | `sys-staff` は宣言した作業に着手できるか。できないなら**どのブロックが外れなかったか** |
| **業務側** | `client-staff`（または `client-boss`）は宣言した判断に進めるか。できないなら**同じく何が外れなかったか** |

**外れなかったブロックが、そのまま次回の議題です。** 宿題（`03_open-issues.md`）に落ちているかを確認してください。
**落ちていないブロックは誰も抱えていないので、次回まで残りません。**

**条件を満たしていなければ、同じ型をもう一度**提案します。同じ型が3回続くのは正常です。
満たしていれば次の型へ。個別の状態も判断材料に加えてください。

- 未消化の宿題が溜まっている → **要件を詰める** をもう一度（質問事項の消化）
- 仮決めが多い → **要件を詰める** をもう一度（本決めへの昇格）
- 画面が社内OKまで進んだ → **画面を決める** へ
- 承認済み画面が出た → **仕様を固める** へ

**どちらの手が止まっているかで、次回の目的の文面が決まります。**

- **システム側が止まっている** → 止めている情報を業務側から取りに行く会議（聞き出す）
- **業務側が止まっている** → 判断材料を出す会議（案を見せる、決められる人を呼ぶ）

提案は `/meeting-open` にそのまま渡せる自由文の形で示すこと（例:
「`/meeting-open 突合の判定基準を詰めたい`」）。

最後に本日のサマリを表で示してください。

```bash
python scripts/clock.py --detail
```

- 使用時間 / 持ち時間、話者別・議題別の内訳
- 発言数・決定数（仮/本の別）・宿題数・仮決めの残数
- **今日扱えなかった議題**（次回に回すもの）

時間切れで積み残しが出るのは正常です。**何が決まって何が残ったかを明確にして閉じること。**
